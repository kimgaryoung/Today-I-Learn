[용어 정리] 

확장성 vs 범용성 

- 확장성(scalability) - 수요 증가나 데이터 양 확대에 맞춰 시스템,서버,기능 등을 추가하여 성능을 높일 수 있는 능력.  (ex 서비스 중단 없이 대량의 트래픽 감당)

- 범용성 (versatility)-특정한 용도에 국한되지 않고 여러 환경,분야에서 사용할 수 있는 성질.(ex 윈도우,mac, 리눅스 동시 지원)

LB(loadBalancer) vs WAS(Web application server)

- LB: 트래픽을 여러 서버로 나누어 분산 (서버 앞단에서 요청을 라우팅함)
- WAS: 클라이언트 요청에 맞는 실시간 데이터 가공 및 응답. (웹 서비스의 핵심 기능 수행)

데이터 무결성 vs 데이터 정합성 

- 데이터 무결성 : 데이터 값이 정확한 상태.(이메일이 형식에 맞게 저장됨)
- 데이터 정합성 : 어떤 데이터 값들이 서로 일치함. (A→ B에 500만원 송금)

 scale-up vs scale-out

- scale-up: 기존 서버의 성능을 업그레이드 하는 것. (ex용량을 증가하기 위해 디스크 추가 or 컴퓨터 cpu,memory의 성능을 올리는 것)
- scale-out: 서버의 갯수를 추가하는 방식

멀티 인스턴스 vs 멀티 테넌시 

- 멀티 인스턴스 : 한명의 서비스를 여러대의 서버에서 띄워둔 상태.
- 멀티 테넌시 : 하나의 서버를 여러명이 분할하여 사용 (SaaS)

# 1. nosql

등장 배경 ) 

데이터의 다양성(데이터의 형식이 다양해짐) , 대규모 데이터 터리 , 수평 확장 및 유연한 설계 요구에 대한 필요성이 증가하고 있음. 

SQL특징 ) 

- 일관성을 보장하니까…유연하지 못함.
- 원자성을 보장하니까(데이터 일관성을 지키려고 대기상태가 발생함) .… 동시 처리성이 낮음
- 확장성이 낮음.

NOSQL)

- doc,key-value, graph등의 유연한 데이터 구조
- join과 트랜잭션이 아닌 → 동시 처리성을 높인
- 수평 확장에 최적화된 가용성과 분할이 가능해 확장성이 높음.

### 1-3. column-oriented store

**:** 테이블 구조처럼 컬럼 단위 데이터 저장, 동일 행 내 컬럼 그룹 관리

[ RDB와 column-oriented store 차이점] 

RDB: ‘학생’이름을 알고 싶으면 ‘학생’ 테이블 전체를 보냄.  행들을 읽고 값을 꺼내서 IO가 많음=속도가 느림

column-oriented store:’학생’의 이름 열만 보냄.

장점 
• 대용량 데이터, 빅데이터 처리 적합
• 컬럼 단위 조회 최적화 →  읽기 성능 좋음

**단점:**
• 설계가 복잡함. 스키마 잘못 설계하면 비효율
• 단순 조회/저장 외 복잡 쿼리는 어려움

사용) 
• 로그 수집, 분석, 시계열 데이터, 추천 시스템
• 속성의 수정이 많거나, 관계성이 낮은 데이터

ex)cassandra, HBRSE

**특징:** 노드와 엣지 구조로 데이터 저장 (관계 중심)

### 3-2 Global Cache

spring Global Cache: 로그인 세션(다른 서버에서도 로그인 유지할때)나 티켓팅(동시에 구매를 눌러도 정상적으로 동작되게)에서 사용함. 

글로벌 캐시는 외부의 독립된 단1대의 캐시 서버에 데이터를 저장하고 여러 서버가 공유하는 방식이라 1의 오차도 없이 똑같은 최신 데이터를 실시간으로 보여줘야 할 때사용함.

 네트워크가 극단적으로 빨라야 하는 임베디드에서는 사용하지 않고 서버 컴퓨터가 1대인 상황에서는 일관성이 깨질일이 없어 사용하지 않아. 

<img width="1355" height="826" alt="image" src="https://github.com/user-attachments/assets/a21575a2-d4b7-4b49-a320-29e864b08e4c" />


```jsx
@Configuration
@EnableCaching // 스프링 캐시 활성화
public class RedisConfig {

    @Bean
    public RedisConnectionFactory redisConnectionFactory() {
        return new LettuceConnectionFactory(); // 기본: localhost:6379
    }

    @Bean
    public RedisTemplate<String, Object> redisTemplate(RedisConnectionFactory factory) {
        RedisTemplate<String, Object> template = new RedisTemplate<>();
        template.setConnectionFactory(factory);
        template.setKeySerializer(new StringRedisSerializer());
        template.setValueSerializer(new GenericJackson2JsonRedisSerializer());
        return template;
    }
}
```
