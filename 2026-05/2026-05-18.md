### 주제 2: 클라이언트-서버

clinet(=user agent) 
: 요청의 시작점, 사용자 인터페이스 구현(브라우저), 컴퓨팅 자원 사용.(ex:엔진엑스 )

server 
: 수동적인 대기,중앙 집중식 자원 관리 + 보안,응답 비지니스 로직과 데이터를 처리함 (비지니스 로직 예 - 우리 회사는 회원가입시 이메일을 중복체크해 같은 대회비 자원은 서버가 처리함)

-web server : 정적 파일을 빠르게 전달하는 서버.(ex: Nginx)
-web application server(WAS) : 동적인 로직을 처리하는 서버 (ex:  spring boot, fastapi) 
-Database server : 데이터를 저장하고 조회하는 서버(ex: mysql)

⭐왜 클라이언트와 서버를 나눌까? 

중앙 집중식으로 클라이언트와 서버가 나눠지지 않았을떄 단점 : 비싸고 병목이 심하다. (중앙에 모든 요청이 몰림)
                  ↓
개인용 컴퓨터 보급되면서 일을 위임해줌. (클라이언트-서버 구조로 나눔)


클라이언트( 뼈대 ) + 서버( 데이터 넣기 )


어떤 장점 때문에 나눴을까?

-사용자 경험이 좋아짐 (화면 부드러움) 
-확장이 쉬워졌음 (서버가 데이터 처리에만 집중)

## 오늘의 생긴 질문과 답변 

Q Web server와 WAS에서  정적, 동적의 차이가 뭘까?

web server는 누가 요청해도 똑같은 결과를 출력하는 것이라 '정적'이라는 표현을 사용하는 것이다. 
예를 들면 로고 사진(logo.png)는 누가 요청하든 똑같은 이미지가 오지만 

WAS는 요청 받을 때 datebase가 실행결과를 만들어서 보내는 것으로 사용자,시간, 입력값,db상태 등등에 따라서 값이 달라져 '동적'이라고 표현하는 것이다. 예를 들어 마이페이지에 접속하면 사람마다 자신의 정보가 나오는 것과 같다. 







## 한줄정리 
- Web : 양방향 소통과 공유가 가능한 플랫폼
- 클라이언트: 요청의 시작이 되는 역할로 사용자 인터페이스를 구현하고 컴퓨팅 자원을 사용하는 주체 (레스토랑에서 손님)
- 서버 : 데이터 제공의 주체로 비지니스 로직과 데이터를 처리함 (비지니스 로직 예 - 우리 회사는 회원가입시 이메일을 중복체크해 같은 대회비 자원은 서버가 처리함)

- HTTP : OS를 따지지 않는 표현법을 전세계의 네트워크상에서 표준화한것.
- HTTP Mesasge:서버와 클라이언트가  request(요청)과 reponse(응답)으로

구조는 시작줄, 헤더, 빈줄, 바디로 구성된 데이터.

- HTTP Method : 자원에 대한 행위를 표현하는 것으로 get,post, put, patch,delete가 있습니다.


- HTTP Status Code : 응답에 대한 코드로 400번대는 클라이언트 오류 ,500번대는 서버 오류 임.
- HTTP URL: 웹상의 자원으로 리소스를 표기하는 주소
