### 주제 2: 클라이언트-서버

: 요청의 시작점, 사용자 인터페이스 구현(브라우저), 컴퓨팅 자원 사용.(ex:엔진엑스 )

server 
: 수동적인 대기,중앙 집중식 자원 관리 + 보안,응답 비지니스 로직과 데이터를 처리함 (비지니스 로직 예 - 우리 회사는 회원가입시 이메일을 중복체크해 같은 대회비 자원은 서버가 처리함)

-Database server : 데이터를 저장하고 조회하는 서버(ex: mysql)

중앙 집중식으로 클라이언트와 서버가 나눠지지 않았을떄 단점 : 비싸고 병목이 심하다. (중앙에 모든 요청이 몰림)
                  ↓

어떤 장점 때문에 나눴을까?

-사용자 경험이 좋아짐 (화면 부드러움) 
-확장이 쉬워졌음 (서버가 데이터 처리에만 집중) 




### 주제 3: HTTP

HTTP=hyperText를 전송하는 통신규약 표준.

HTTP : hyper/text/transfer/protocol

Text vs HyperText

-Text: 우리랑 상호작용 X ( 우리가 클릭한다고 반응 X) 
-Hypertext: 문자인데 이미지, 문자인데 링크, 문자인데 목록 


if) HTTP가 없다면 -> 전세계 컴퓨터가 자신의 방식으로 HT(Hypertext) 전송, 내가 원하는 의도가 전달될 수 없음. 

- os를 따지지 않음.(브라우저도 따지지 않음)
- 전세계의 네트워크의 공통 통신 규약.


HTTP 사용 방법 ) client가 URL을 통해 특정 웹 주소로 접근하면 해당 주소의 서버로 HTTP 요청(request)을 보냄.

### 주제 5: HTTP request Method⭐⭐
: 웹 서버에게 어떤 작업을 수행하길 원하는 지 알리는 방법을 정의하는 명령 규칙.

Q 왜 HTTP method를 따로 사용하는 걸까? 

HTTP Method  사용이유1) 
캐싱, 웹에 사용자 증가하며 트래픽도 증가하게됨.  Method없이 요청을 보내는 경우, 모든 요청을 다 열어서 어떤 내용인지 확인하면 시간이 오래 걸려 부하가 됨. method가  있는 경우 바디를 열지 않고도 판단할 수 있음. (get요청→ 조회구나 → 캐시 반환)

HTTP Method  사용이유2)
보안 , 계좌에서 돈을 출금할때 서버를 열어봐야하는데 권한 확인이 필요함. HTTP Method없이 모든 검사 요청마다 다 확인하면 부하가 발생함. (method만 보고도 미리 거절가능함)


사용 방법 ) 웹 요청을 보낼 때, URL과 함꼐 메소드를 명시하여  서버에게 특정 작업을 요청하면 됨. 

<메소드 종류>
GET : 가져오기(조회) 
Post: 생성 
Put : 전체 수정(대체)
Patch : 일부 수정 
Delete : 삭제

### 주제 9: RESTful API

rest : Representational State Transfer/ 

자원을 이름으로 식별하고(Representational)   → 자원 글자나 데이터 형태로 표현한다.
해당 자원의 상태를 구조화된 형식으로 표현하여(State) → 자원의 현재 정보를 의미한다.
서버와 클라이언트 간에 정보를 교환하는 방식 (Transfer) → 클라이언트와 서버가 그 정보를 주고받는다.


api : application program interface / 내가 만든 애플리케이션과 이미 만들어진 애플리케이션이 서로 통신할 수 있도록 정의한 명세서.


restapi : 자원과 행위를 명시하는 API 설계 방법으로 자원은 명사로 행위는 method로 표현하는 소프트 아키텍쳐 방법 중 하나.

Q Web server와 WAS에서  정적, 동적의 차이가 뭘까?

web server는 누가 요청해도 똑같은 결과를 출력하는 것이라 '정적'이라는 표현을 사용하는 것이다. 
예를 들면 로고 사진(logo.png)는 누가 요청하든 똑같은 이미지가 오지만 

WAS는 요청 받을 때 datebase가 실행결과를 만들어서 보내는 것으로 사용자,시간, 입력값,db상태 등등에 따라서 값이 달라져 '동적'이라고 표현하는 것이다. 예를 들어 마이페이지에 접속하면 사람마다 자신의 정보가 나오는 것과 같다. 







## 한줄정리 
- Web : 양방향 소통과 공유가 가능한 플랫폼.
  
- 클라이언트: 요청의 시작이 되는 역할로 사용자 인터페이스를 구현하고 컴퓨팅 자원을 사용하는 주체 (레스토랑에서 손님)
  
- 서버 : 데이터 제공의 주체로 비지니스 로직과 데이터를 처리함 (비지니스 로직 예 - 우리 회사는 회원가입시 이메일을 중복체크해 같은 대회비 자원은 서버가 처리함)

- HTTP : hyperText를 전송하는 통신규약 표준.
  
- HTTP Mesasge:서버와 클라이언트가  request(요청)과 reponse(응답)으로 구조는 시작줄, 헤더, 빈줄, 바디로 구성된 데이터.

- HTTP Method : 자원에 대한 행위를 표현하는 것으로 get,post, put, patch,delete가 있습니다.

- HTTP Status Code : 응답에 대한 코드로 400번대는 클라이언트 오류,500번대는 서버 오류임.
  
- HTTP URL: 웹상의 자원을 위치를 표시하는 주소. 

- RESTful API :자원과 행위를 명시하는 API 설계 방법으로 자원은 명사로 행위는 method로 표현하는 소프트 아키텍쳐 방법 중 하나.
