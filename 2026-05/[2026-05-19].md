## 한 줄 정리

Spring Web MVC : Model, View, Controller로  코드의 책임을 분리하는 MVC패턴을 웹 프레임워크에 적용한것으로 데이터,화면, 요청 처리를 분리해서 코드 관리가 쉬워 자주 사용됨. 

DispatcherServlet : 공통로직을 처리하는 서플릿으로 MVC패턴에서  요청을 담당할 컨트롤러를 찾아달라고HandlerMapping에게 명령어하거나 view에서 사용자가 원하는 것을 출력해주는 역할을 한다. 

대칭키 : 암호화와 복호화를 대칭키로 하는 방식이고 처리는 빠르지만 보안에 취약하다.

비대칭키 : 개인키와 공개키가 존재하며 공개키로 암호화한 내용은  개인키로만 복호화하는 방식이다. 공개키 기반 인증서를 통해 서버를 인증해줄 수 있다. 보안에는 뛰어나지만 처리속도가 느리다. 

HTTPS : HTTP의 응답과 요청을 암호화하여 주고 받는 통신 방식으로 이 과정을 위해서 TLS handshack과정에서 서버는 인증기관에 전달하고 클라이언트 인증기관의 공개키로 인증서를 검증한다.

## 질문/응답 

- Q 서블릿이 뭔가요?

서블릿은 HTTP 요청을 해석하고 응답을  만들어주는   java 클래스입니다. 

과거에는 개발자가 요청마다 직접 서블릿을 만들어 처리 했습니다.   유저의 요청이 1000개라면 1000개의 서블릿을 만들어야 했습니다.

MVC가 등장하고 DispatcherServlet이라는 하나의 서블릿이 모든 요청을 먼저 받고 HandlerMapping을 통해 알맞은 Controller를 찾아 실행하는 방식으로 변경되면서 개발자는 controller의 비지니스 로직을 작성하는데 집중하게 되었습니다.

- Q HTTPS의 키교환 방식을 설명해보세요.(면접 빈출)
 서버는 먼저 인증기관으로부터 공개키가 포함된 인증서를 발급받습니다. 
이후 TLS Handshake 과정에서 서버는 클라이언트에게 인증서를 전달하고 클라이언트는 CA의 공개키로 인증서를 검증하여 서버를 신뢰할 수 있는지 확인합니다.
 그 다음 클라이언트는 대칭키를 생성하고 서버의 공개키로 암호화해 전달합니다. 
 서버는 자신의 개인키로 이를 복호화하여 같은 대칭키를 획득합니다.
