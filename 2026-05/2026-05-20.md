## 주제 1:OOP 

개념 : OOP의 고유 명사는 **현실 세계의 객체 개념을 기반으로 데이터를 속성(필드)과 기능(메서드)로 묶어 프로그램을 설계하는 패러다임**입니다.<br>
<br>
<br>
- 객체 : 역할과 책임을 가진 주체 (누가 책임 질래? → A객체가 책임짐)<br>
- OOP : 역할과 책임을 가지고 있는 주체의 OO으로 바꾸는 것<br>
<br>
⚠️ 객체에 대해 오해하는 포인트 : 객체는 데이터를 담은 상자(X)<br>
ex) 커피 ←아이스 아메리카노 인  경우  다른 점이 ‘온도’ 밖에 없음. 좋은 설계가 아님.

```java
// 안 좋은 설계 예시
public class Coffee {
    protected String temperature = "HOT";
}

public class IceAmericano extends Coffee {
    public IceAmericano() {
        this.temperature = "ICE"; 
    }
}
```

# 오늘의 생긴 질문과 답변
<br>
<br>

**Q1 JVM 이 하는 일은?<br>**
: 자바 바이트 코드 OS에 맞는 기계어로 번역하여 실행함.
<br>
<br>
 **Q2 class loader의 역할<br>**
: 바이크 코드를 method area에 적재하는 역할을 함.
<br>
<br>
 **Q3 실행 엔진이 하는 일은?<br>**
: 메모리에 로드된 바이크 코드를 인터프리터나 JIT 컴파일러를 통해 기계어로 바꿈.
<br> 
<br>
**Q4 jit은 어떻게 동작하나요?<br>**  
 : 인터프리터가 바이트 코드를 한줄씩 번역할때  각 코드의 실행횟수를 카운트해서 자주 쓰이는 코드는 통째로 기계어로 컴파일해 캐싱해두었다가 재사용함. 
<br> 
<br>
**Q JAVA가 왜 하이브리드 언어라고 할까? (수업중 질문)<br>** 

컴파일과 인터프리터 모두 일어나서.<br>  
컴파일 : java 소스파일(.java)가 java 컴파일러(javac)에 의해 컴파일 되어 바이트 코드 생성.<br> 
인터프리트 : 바이크 코드는 JVM내부 인터프리터를 통해서 OS가 이해할 수 있는 기계어로 번역됨.<br>  
JIT 컴파일러 : JVM의 내부 인터프리터의 속도가 느리기 때문에 자주 사용하는 코드를 기계어로 컴파일하여 캐싱해둠.<br>
