public interface Engine() {
	void start();
}


	
// 3. 자동차 (조율자)
public class Car {
    private final Engine engine; // 의존성 
    private final Brake brake; //의존성 

    public Car(Engine engine, Brake brake) {
        this.engine = engine; //주입-외부에서 받아옴
        this.brake = brake; //주입- 외부에서 받아옴
    }

    public void start() { engine.start(); } // 엔진에게 책임 위임
    public void stop() { brake.apply(); }   // 브레이크에게 책임 위임
}

## 주제 3:SOLID-OCP,DIP

### OCP

**소프트웨어의 기능 확장은 열려 있고, 기존 코드의 변경은 닫혀 있어야 한다<br>**.
<br>
개방 : 새로운 기능을 추가하거나 확장에는 항상 열려 있어야 함<br>
패쇄 :그로 인해서 기존 코드가 수정되는 것에는 닫혀있어야 함.<br> 

→ 새 기능 추가시 이미 잘 돌아가는 예전 코드에 손대지 않게 !<br>
<br>
실무에서 OCP원칙이 중요한 이유<br> 
- 내가 개발하지 않은 코드가 프로젝트 안에 99%가 넘음.

## DIP

**상위 모듈(정책을 결정하는 코드)이 하위 모듈(세부 구현 코드)에 직접 의존하지 않고, 양쪽 모두 추상화(인터페이스나 추상 클래스)에 의존해야 한다는 객체지향 설계 원칙**
<br>
<br>
상위 모듈 : 엔진은 동력 바퀴에 전달된다 <br>
하위 모듈 : 엔진이 가솔린 → 전기 모터로 변경됨<br>
<br>
<br>
<details>

    // 엔진 하나 바꿨는데 주행 서비스 코드가 통째로 깨지고 수정됨 (Inversion 실패)

```java
// 1. 대원칙이자 역할인 "인터페이스"를 선언 (추상화)
public interface Engine {
    void start();
}

// 2. 가솔린과 전기는 이제 이 규격에 자신을 맞춤 (저수준이 추상화에 의존)
public class GasolineEngine implements Engine {
    public void start() { System.out.println("가솔린 엔진을 시동합니다."); }
}

public class ElectricEngine implements Engine {
    public void start() { System.out.println("배터리 전원을 켭니다."); }
}

public class DrivingService {
    // 특정 엔진 이름을 지워버림. 오직 Engine 역할에만 의존
    private final Engine engine;

    // 내가 직접 new하지 않고, 외부에서 주는 대로 받음 (의존성 주입)
    public DrivingService(Engine engine) {
        this.engine = engine;
    }

    public void drive() {
        engine.start(); // 어떤 엔진이든 start() 계약만 충족하면 실행 가능
        System.out.println("주행을 시작합니다.");
    }
}
```

#### Class Loader
바이트 코드를 확인하고  method area에 올리는 역할.<br>


| 구분 | 주요 내용 | 상세 설명 |
| :--- | :--- | :--- |
| **메타데이터** | 클래스, 인터페이스, 필드 | 해당 바이트 파일의 구조를 정의하는 기본 정보 |
| **상수 풀 (Constant Pool)** | 선언된 상수, 상수의 인덱스 | 프로그램 내에서 사용되는 리터럴 상수와 참조 정보 관리 |
| **메서드** | 실제 구현 로직 | 클래스 내부에 정의된 메서드의 실행 가능한 바이트코드 |
| **속성 (Attributes)** | 부가 정보들 (소스 파일 이름, 디버깅 정보 등) | 컴파일 및 디버깅 등에 필요한 추가적인 메타데이터 |

JIT 컴파일러 : JVM의 내부 인터프리터의 속도가 느리기 때문에 자주 사용하는 코드를 기계어로 컴파일하여 캐싱해둠.<br>
