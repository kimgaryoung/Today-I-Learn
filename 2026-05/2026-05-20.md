## 주제 3:SOLID-OCP,DIP

###OCP

**소프트웨어의 기능 확장은 열려 있고, 기존 코드의 변경은 닫혀 있어야 한다<br>**.
<br>
개방 : 새로운 기능을 추가하거나 확장에는 항상 열려 있어야 함<br>
패쇄 :그로 인해서 기존 코드가 수정되는 것에는 닫혀있어야 함.<br> 

→ 새 기능 추가시 이미 잘 돌아가는 예전 코드에 손대지 않게 !<br>
<br>
실무에서 OCP원칙이 중요한 이유<br> 
- 내가 개발하지 않은 코드가 프로젝트 안에 99%가 넘음.

<details>
<summary>예시코드 - 결제 </summary>
### 잘못된 예 )결제 로직 추가 변경시 closed위반 <br> 

```java
public class PaymentService {

    public void processPayment(String method, int amount) {
        if (method.equals("NAVER_PAY")) {
            System.out.println("네이버페이 결제 로직...");
        } else if (method.equals("TOSS_PAY")) {
            System.out.println("토스페이 결제 로직...");
        }
        // 만약 카카오페이가 추가된다면?
        // 또 이 파일(기존 코드)을 열어서 else if를 추가해야 함. -> Closed 위반
        else if (method.equals("KAKAO_PAY")) {
            System.out.println("카카오페이 결제 로직...");
        }
    }
}
```

### OCP가 지켜진 예 )interface 도입 <br>

    ```java
    // 1. 결제라는 역할 (규격화된 USB 포트)
interface Payment {
    void pay(int amount);
}

// 2. 새로운 기능은 "클래스 추가"로 구현한다 (Open)
class NaverPay implements Payment {
    public void pay(int amount) { System.out.println("네이버페이 결제"); }
}

class TossPay implements Payment {
    public void pay(int amount) { System.out.println("토스페이 결제"); }
}

class KakaoPay implements Payment { // 새로 추가된 카카오페이
    public void pay(int amount) { System.out.println("카카오페이 결제"); }
}

public class PaymentService {
    private final Payment payment; // 특정 회사가 아닌 "역할"에 의존

    public PaymentService(Payment payment) {
        this.payment = payment;
    }

    public void process(int amount) {
        payment.pay(amount); // 다형성 
    }
}
    ```

# 오늘의 생긴 질문과 답변
<br>
<br>

**Q1 JVM 이 하는 일은?<br>**
: 자바 바이트 코드 OS에 맞는 기계어로 번역하여 실행함.
<br>
<br>
 **Q2 class loader의 역할<br>**
: 바이크 코드를 method area에 적재하는 역할을 함.
<br>
<br>
 **Q3 실행 엔진이 하는 일은?<br>**
: 메모리에 로드된 바이크 코드를 인터프리터나 JIT 컴파일러를 통해 기계어로 바꿈.
<br> 
<br>
**Q4 jit은 어떻게 동작하나요?<br>**  
 : 인터프리터가 바이트 코드를 한줄씩 번역할때  각 코드의 실행횟수를 카운트해서 자주 쓰이는 코드는 통째로 기계어로 컴파일해 캐싱해두었다가 재사용함. 
<br> 
<br>
**Q JAVA가 왜 하이브리드 언어라고 할까? (수업중 질문)<br>** 

컴파일과 인터프리터 모두 일어나서.<br>  
컴파일 : java 소스파일(.java)가 java 컴파일러(javac)에 의해 컴파일 되어 바이트 코드 생성.<br> 
인터프리트 : 바이크 코드는 JVM내부 인터프리터를 통해서 OS가 이해할 수 있는 기계어로 번역됨.<br>  
JIT 컴파일러 : JVM의 내부 인터프리터의 속도가 느리기 때문에 자주 사용하는 코드를 기계어로 컴파일하여 캐싱해둠.<br>
