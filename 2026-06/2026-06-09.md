# 2. 스케줄러

: 시스템의 자원을 분배하기 위해서 프로세스나 스레드의 실행순서를 관리함.

### 2-1 왜?

1. 자원 독점 문제 해결
   - 자원을 많이 쓰는 무거운 연산이 들어온다면 cpu가 이것만 처리하고 다른 작업은 아예 수행하지 못함.
2. 기아 상태 해결
   - "먼저 온 애부터 하자", "가장 급한 프로세스 먼저 하자" : 이렇게 처리할 경우 처리되지 못하고 계속 작업이 밀리는 경우가 발생함.
3. 시스템 낭비적인 측면 해결
   - 디스크 I/O를 동작하는 동안 CPU는 기다려야 하는데 이때 다른 작업을 처리하면 효율이 높아짐.

### 2-2 스케줄러 목표

1. cpu 이용율 최대화 : cpu가 컴퓨터 자원 중에 가장 비싼 자원이기 때문에 최대한 잘 쓰고 싶다.
2. 처리량을 늘리고 싶다. : 백엔드 서버에서 1초에 처리할 수 있는 처리량인 동시 처리량을 늘리고 싶다.
3. 총 처리 시간 감소 =대기 시간 최소화 =응답 시간 최소화.

### 2-3 스케줄러 기능.

1. 작업 선택 : 현재 실행 가능한 프로세스,스레드 중에서 다음에 어떤 CPU할당할지 고름. (스케줄링 알고리즘: RR, SJF..)
2. 자원 분배 : 선택한 작업 CPU 권한 분배해줌. 타임 슬라이스로 잘라서 부여.
3. 컨텍스트 스위칭 관리 : 기존작업에서 새 작업을 불러옴 ( 기존 작업 상태를 PCB에 저장하고 새 작업 PCB를 불러옴)

### 2-4 스케줄러의 종류

1. 장기 스케줄러
   - 역할 : 보조기억장치에 있는 프로그램 중에서 어떤걸 RAM에 올리고 어떻게 실행 프로세스를 만들지
   - 특징 : 한번에 많은 프로세스가 시스템이 올라오지 않도록 제어함. 현대에서는 RAM이 싸져서 OS에서 잘 사용 안됨.

2. 중기 스케줄러 (스왑 관리자)
   - 역할 : 메모리를 쓰다가 부족하면 활성화된 프로세스 중 일부를 중단 시키고 Disk에 스왑 영역으로 옮기고 메모리가 여유로워지면 다시 가져온다.

3. 단기 스케줄러 (CPU 스케줄러) \*\*우리가 생각하는 스케줄러!<br>
: 메모리의 준비 상태로 있는 프로세스 중에서 cpu를 할당 받을 프로세스를 결정하고 ms단위로 빠르게 동작해서 속도가 상당히 빠름.

### 2-5 스케줄러 동작 방식

1. 작업 대기열 관리 : 대기큐에 추가.
2. 우선순위 설정 : 어떤 우선순위 알고리즘으로 실행할지 실행순서 결정.
3. 자원 분배 : 작업에 필요한 cpu,메모리등 자원을 할당.
4. 작업 전환 : 컨텍스트 스위칭
5. 완료,자원 해제

# 3. 스케줄링

: cpu와 같은 자원을 프로세스와 스레드들이 사용할 수 있도록 줄을 세우는 과정.<br>
: 동시에 병렬적으로 어떤 걸 언제, 얼만큼 실행할까를 결정하는 규칙과 정책

### 3-1 스케줄러 vs 스케줄링

스케줄러 : 자원 할당, 스케줄 관리하는 주체.<br>
스케줄링 : CPU를 사용할 순서를 결정하는 운영체제의 정책.

### 3-2 스케줄링의 목표

- cpu이용률 증가 : cpu가 놀지 않고 계속 쓰이게 함.
- 처리량 증가 : 더 많은 작업을 처리
- 응답시간 감소 : 사용자 요청에 빠르게 반응하게 함.
- 대기시간 감소 : 프로세스가 기다리는 시간 최소화 함.
- 공정성 확보 : 특정 프로세스 독점 방지

### 3-3 스케줄링 레벨

- 고수준 스케줄링 : 메모리에 올릴 프로세스 결정 (시스템의 전체 부하를 조절하는 걸 목표로 함)
- 중간 스케줄링 : 메모리가 부족할 때 일부 프로세스를 잠시 내보냄 ,Swap과 유사 (시스템의 안정성을 유지를 목표로 함)
- 저수준 스케줄링 : CPU를 누구한테 할당할지 , 보통의 우리가 말하는 스케줄링 ,실행 빈도가 짧고 많이 실행이됨.

스케줄링 정책 설정 - 자원 분배와 성능 최적화를 위해!!!

| 목표 | 설정 | |
|---|---|---|
| 서버 환경 | 성능 극대화를 목표로 처리량을 높이는 정책을 선택함. | 가성비한 서버 (RESTAPI)는 AWS사용함. |
| 실시간 시스템 | 응답 시간을 최소화하고 시간 제약을 충족하는 정책. | 게임서버,실시간성이 높은 서버는 비싸서 AWS에 사용 안하고 IDC,NHN을 사용함. |
| 데스크톱 환경 | 사용자 응답성을 최우선으로 다중 작업 간 공정성을 유지하는 정책을 선택. | |

### 3-5 스케줄링 알고리즘

**FCFS** : 먼저온 작업 먼저 처리
- 장점 : 구현이 쉬움
- 단점 : (Convoy Effect) 먼저 온 프로세스가 작업 시간이 길면 전체 프로세스가 다 기다려야한다.

**SJF (Shortest job First)** : 가장 짧은 작업 먼저 처리
- 장점 : 평균 대기 시간이 제일 적음. OS에서 가장 효율 적임.
- 단점 : 프로세스가 실행될 시간을 예측하기 힘듦 + 기아 현상

**SRTF(Shortest Remaining Time First)** : 남은 시간이 가장 짧은 프로세스를 실행, SJF의 선점형 버전
- 장점 : 응답성이 좋아짐.
- 단점 : 컨텍스트 스위칭 비용이 높아짐.

**Priority** : 우선 순위 높은 프로세스 실행
- 장점 : 중요한 작업을 먼저할 수 있음(다른 알고리즘에서는 중요한 작업이 빨리 끝나지 않음)
- 단점 : 기아상태.

**Round Robin** : 모든 프로세스에게 동일한 CPU 시간 제공.
- 장점 : 공정하고 응답성 나쁘지 않음.
- 단점 : 타임 슬라이스가 너무 작으면 컨텍스트 스위칭이 커짐, 타임 슬라이스가 너무 커지면 응답성이 안좋아짐.

**선점형 VS 비선점형** ( cpu를 강제로 뺏을 수 있냐 없냐 )<br>
선점형 : OS가 CPU의 자원 강제 회수 , 현재의 OS는 모두 선점형 → 보통 여러 작업을 동시에 실행하기 때문.<br>
비선점형 : 강제 회수 X, 끝날때까지 기다려야함.

# 4. Multilevel Queue

: 프로세스를 그룹별로 나눠서 관리함.<br>
: 프로세스 종류별로 큐를 나누고 큐 마다 다른 스케줄링 알고리즘을 적용하는 방식.

실시간 작업 큐-(음성통화) - Priority 스케줄링<br>
일반 사용자 작업 큐 -(메신저 )-RR스케줄링<br>
배치 작업 큐 -(백업, 대용량 데이터 저장)-FCFS

현재의 운영체제는 섞어서 사용함.
- Linux : 우선순위 + RR + Fair스케줄링 + 로드밸런싱
- 윈도우 : 동적 우선순위 +라운드로빈

### 현업 )

백엔드 개발자 : 사용 X( 운영체제에서 이미 결정되어 있음) BUT 성능 최적화 -트러블 슈팅에 사용함.<br>
ex) CPU가 사용량은 남았는데 처리량이 안나올때 ⇒ 스레드 수가 과다하거나 컨텍스트 스위칭만 엄청하거나.

인프라 엔지니어 : 일부 사용
- Linux에서는 nice, renice 명령어를 사용해 프로세스의 우선순위를 변경할 수 있음
- CPU Affinity를 통해 특정 프로세스를 특정 CPU 코어에서만 실행하도록 설정할 수 있음.
- 쿠버네티스에서는 CPU 요청량과 제한량을 설정하여 컨테이너의 CPU 할당 정책을 관리하는데 사용.

# 4. 병렬성

: 여러 CPU코어 또는 다중 프로세서를 사용하여 여러 작업을 물리적으로 동시에 실행하는 개념<br>
: 여러개의 CPU 코어를 활용해서 여러 작업을 동시 수행하려고 하는것 (시스템의 성능을 극대화)

### 4-1 왜?

→ 시스템의 성능을 극대화

| 이유 | 설명 |
|---|---|
| 성능 향상 | 여러 작업을 동시에 처리하여 실행시간 단축 |
| CPU 활용도 증가 | 여러 코어를 모두 활용 가능. |
| 실시간 처리 | 게임, 스트리밍. 영상처리에 빠른 응답 제공 |
| 대규모 데이터 처리 | 머신러닝,빅데이터 분석 속도 향상 |

### 4-2 병렬성 vs 동시성

동시성 : 동시에 처리하는 것처럼 보이는 것 . (1개의 코어)<br>
병렬성 : 실제로 동시에 실행되는것. (n개의 코어 필수)

### 4-3 병렬성 특징

- 실제 동시 실행 : 여러 코어에서 동시에 실행
- 하드웨어 의존 : 멀티 코어 CPU 필요
- 작업 독립성 : 작업간 간섭이 적어야 함.
- 계산 중심 작업에 적합 : 머신러닝, 영상처리, 시뮬레이션

### 4-4 병렬 동작 방식 ( 작업을 분할 → 코어 할당 → 병렬 실행 → 결과 통합 )

1. 작업 분할 : 하나의 큰 작업을 여러개로 나눔.
2. 코어 할당 : ?
3. 병렬실행 : ?
4. 결과 통합 : 각각의 결과물을 최종 결과로 총합.
5. 오류 처리

### 4-5 현업)

1. 게임
2. 영상작업<br>
   영상의 화질을 올리는 작업(512p → 4K)<br>
   유튜브 : 통신비를 낮추기 위해서 발송지에서 512p로 보내고 수신지에서 받은 다음 4K로 변환하는 방식.
3. 인공지능 학습.

### 4-6 실무 tip)

1. 병렬성은 항상 정답이 아님.<br>
병렬이 항상 빠른 작업 속도를 보장하지 않고 작업을 분할하고 결과 합치는 비용이 생각보다 비쌈.<br>
(작업 분할 비용 + 스레드 생성비용 + 결과 병합 비용 )< 싱글 코어 동시성 : 명백히 차이가 날때만 사용하자

2. 공유 자원 접근을 조심해야함.<br>
여러대의 코어가 병렬로 처리되는데 동시에 자원에 접근할때 레이스 컨디션이 발생할 수 있음.

3. 물리적 제한 을 잘 조사해야함.<br>
CPU의 코어 수를 잘 살펴봐야함. 8코어라면 동시 병렬은 8코어까지만 가능함.

## 용어정리

**동시성** : 작업을 작은 단위로 나눠서 짧은 실행시간을 할당하고 관리함. 하나의 CPU내에서 일어나는 스케줄링임.<br>
**병렬성** : 여러개의 CPU코어를 활용해서 물리적으로 여러 작업을 동시 수행하는 것<br>
**스케줄러** : 시스템의 자원을 분배하기 위해서 프로세스나 스레드의 실행순서를 관리하는 주체<br>
**스케줄링** : cpu(자원)를 사용할 프로세스와 스레드의 사용할 순서를 정하는 OS 규칙과 정책<br>
**Multilevel Queue** : 프로세스 종류별로 큐를 나누고 큐 마다 다른 스케줄링 알고리즘을 적용하는 방식.
