# [한줄 정리]

- **Network** : 연결된 장치끼리 데이터를 전달 받는것.
- **NIC** : 컴퓨터가 다른 노드와 연결되어 데이터를 전달 받을 수 있게 하는 HW장치
- **Mac Address** : NIC에 부여된 고유한 물리적 식별자로 같은 네트워크 안에서 장치를 구분하는 주소.
- **Gateway** : 서로 다른 네트워크를 연결하려 통신을 가능하게 하는 장치(내부망, 외부망 연결)
- **Router** : 서로 다른 네트워크를 연결하고 IP주소를 보고 패킷이 갈 다음 경로를 결정하는 장비.
- **Switch** : 같은 네트워크 안에서 Mac주소를 보고 데이터를 필요한 장치에만 전달하는 장비 (허브의 단점을 보완함)

> **Q)** AP와 공유기 차이가 뭘까 ??<br>
> 공유기는 인터넷 주소(IP)를 만들어내는 기기이고, AP가 공유기가 만든 IP를 Wi-Fi(무선 신호)를 만들어내는 기기.

> **Q)** 서로 다른 네트워크의 기준이 뭘까? IP 기준 (내부망 끼리도 IP가 다르면 서로 다른 네트워크임)

> **Q)** MAC 헤더, IP헤더는 누가 붙이는 걸까? MAC헤더는 NIC가 붙이고, IP헤더는 OS가 붙임.

# 2. 노드

: 메세지가 지나가는 과정, 데이터를 보내거나 받거나 전달하는 지점.<br>
- **주소를 가진다.** = 노드의 특징 (MAC, IP)

### 왜?

노드가 있어야 네트워크에서 데이터가 흐를 수 있음.<br>
네트워크는 단순히 케이블만 있는게 아니라 데이터를 주고 받는 장치들이 있어야 함

```
내 컴퓨터 -> 공유기 -> 인터넷 -> 웹서버
```

**호스트 vs 노드**

**노드** : 호스트 + 네트워크에서 데이터를 송수신 하거나 전달하는 장치. (서버, PC, 스위치, wifi)<br>
**호스트** : 사용자 대신해서 실제 데이터를 생성하거나 소비하는 최종 장치 (서버, PC)

### 웹 개발 환경에서 노드는 무엇이 있을까?

- **클라이언트 노드** : 브라우저가 실행 중인 내 컴퓨터
- **서버 노드** : 웹 서비스를 제공하는 서버
- **네트워크 노드** : 중간에서 패킷을 전달하는 라우터, 스위치

### 실무에서의 노드

장애가 발생하면 어떤 "노드" 에서 장애가 발생했나?
- 로드밸런서
- API 서버
- 프록시 서버
- 클라이언트 브라우저
- 데이터베이스

**클라우드에서의 노드**
- AWS
  - CloudFront
  - WAF
  - ALB
  - EC2, RDS
  - ElastiCache

# 3. LAN

: 제한된 공간에서 장치들이 빠르게 통신하고 자원을 공유하기 위한 내부 네트워크<br>
= 지역망 = 내부 네트워크

**인터넷 VS LAN**

LAN = 네트워크 BUT LAN ≠ 인터넷
- 내 컴퓨터가 구글에 접속한다 = 인터넷 통신
- 내 컴퓨터가 회사 공용 프린터를 쓴다 = 랜 통신

### 왜?

- <span style="color:red">빠른 내부 통신</span>이 가능해짐 (인터넷을 거치지 않음. 가까운 거리의 장치끼리 데이터를 빠르게 주고 받을 수 있음)
- 자원 공유가 쉽다
- 범위가 작다.

### point

1. 보통 같은 네트워크 대역대를 가짐. (같은 사설 IP 대역을 사용한다)
2. LAN 내부 통신에서는 라우터가 필요 없다.
3. LAN을 설계 하는게 네트워크 설계의 출발점이 됨 (서버실, 컴퓨터, 프린트)
4. 장애를 LAN 단위로 격리해서 해결할 수 있다.

> 💡 노트북, 프린터, 스마트폰 → 스위치, 공유기(wifi) → 라우터

### 장점

- 보완성이 좋아진다.
  - 프로덕션(서비스 환경) = 공개, 개발 서버 (개발 테스트 서버) = LAN
- 통신 속도가 빠르다.
- 비용도 안낸다.

### 인프라 엔지니어 관점

- LAN 을 설계하는게 네트워크 설계의 출발지점
- 사무실 네트워크 구성
  - 컴퓨터, 프린터, 서버 분리해서 사용
- 서버실 = 랜 구성
- 장애 대응
  - 랜 단위로 장애 대응
- 보안 설계
- 성능 이슈 해결

# 3. WLAN, VLAN

**WLAN** : 연결선 없는 LAN (wifi)

### WLAN 구성

| 항목 | 설명 |
|---|---|
| **무선 단말** | 노트북, 스마트폰, 태블릿, IoT 장치 |
| **무선 NIC** | 장치가 Wi-Fi에 연결되기 위한 네트워크 인터페이스 |
| **AP, Access Point** | 무선 장치들을 네트워크에 연결해주는 장비 |
| **SSID** | 사용자가 보는 Wi-Fi 이름 |
| **인증/암호화** | 비밀번호, WPA2/WPA3 같은 무선 보안 |

- 공유기 = 라우터 + 스위치 + 무선AP + NAT + 게이트웨이를 합친 장비.
- IoT 디바이스를 기반으로 하는 회사에서 사용.

### 주의 할점

- 전파로 통신하기 때문에 신호 간섭이 있음
- 무선 신호는 공기 중으로 퍼지기 때문에 보안 문제가 발생할 수 있음. (공개 와이파이에서 통신하는 내용은 다 볼 수 있음)

### <span style="color:red">VLAN</span>

: 하나의 물리적인 네트워크를 여러개의 독립된 네트워크처럼 나누는 기술.<br>
: 연결된 네트워크를 논리적으로 분리 (물리적으로는 하나의 스위치를 사용함)

**왜?**<br>
부서별, 사용자 유형별로 네트워크 접근 범위를 제한해서 보안을 강화할 수 있음.<br>
트래픽 감소 = 브로드캐스트 도메인을 나누어 불필요한 트래픽 확산 방지

| 용어 | 설명 |
|---|---|
| **브로드캐스트** | 같은 네트워크 안의 모든 장치에게 보내는 통신 |
| **브로드캐스트 도메인** | 브로드캐스트가 전달되는 범위 |
| **VLAN의 역할** | 브로드캐스트 도메인을 논리적으로 분리 |

**VLAN 주의 사항**
- 운양 복잡도가 증가함. (네트워크가 커질수록 ip대역이나 정책 관리가 중요)
- 방문객 wifi는 VLAN에 두면 안되고 게스트 망에 분리해야한다.

### PAN < LAN < MAN < WAN

- **MAN** : 여러 건물간의 네트워크 (캠퍼스 단위 네트워크 - 기숙사, 공학관, 도서관, 본관)
- **WAN** : 국가나 대륙 단위의 네트워크 (AWS)
- **PAN** : 개인 주변 장치들을 연결하는 네트워크 (에어팟, 워치, NFC)

# 네트워크 장비

호스트에서 데이터 발송

# 1. NIC (network interface)

: 노드들이 네트워크에 연결될 수 있게 하는 하드웨어<br>
: NIC는 호스트랑 네트워크 사이에서 데이터를 보내고 받는 역할.

**1-1 유선 NIC** : 고정 장치(컴퓨터, 서버)에서 랜선으로 물리적으로 연결, 안정적이고 빠름.<br>
**1-2 무선 NIC** : 와이파이 네트워크에 연결할때 사용, 이동성이 있고 공간의 제약이 없음

# 2. MAC

### 2-1 MAC Address

: 맥 주소는 NIC에 부여된 고유한 물리적 식별자 (같은 네트워크 안에서 장치를 구분하는 주소)<br>
: LAN안에서 어떤 장치에게 데이터를 전달할때 판별하는 역할로 사용함.

**왜?**<br>
네트워크 안에서 실제 장치를 찾아야 하기 때문에 (IP주소는 목적지 네트워크를 찾는 용도)

### 특징

- 호스트에 하나의 NIC가 들어 있으면 = 호스트 1개의 MAC address
- 호스트가 여러개의 NIC가 있으면 = 여러개의 MAC address
- 노트북 와이파이가 변경되면 할당된 IP주소가 변경됨.

**실제 MAC주소 통신 (노트북 → 프린터)**<br>
내 노트북은 프린터의 IP주소를 알고 있지만 실제 LAN안에 데이터를 보내려면 프린터의 MAC주소를 알아야 한다. ( **ARP** : IP주소에 해당하는 MAC주소를 알아내는 프로토콜 )

**MAC 언제까지 사용?**<br>
같은 네트워크 구간에서 전달할때만 사용한다. (컴퓨터 → 구글서버)

```
컴퓨터 -> 공유기 -> ISP -> 여러개의 라우터 -> 구글 서버
```

컴퓨터가 보낼때 최종 목적지는 구글 서버 IP이지만 다음 가야하는 곳은 공유기 맥주소이고<br>
목적지의 MAC주소를 알고 가는 건 아니지만 바로 앞 장비의 MAC주소는 알고 보냄

**MAC address Spoofing**
- 노드의 원래 MAC 주소를 다른 MAC 주소처럼 보이게하는 기술 (공유기 가로채기)

# 3. 리피터

: 물리계층에서 동작하고 통신할 때 보낼 수록 약해지는 신호를 증폭하는 역할.

**리피터의 한계지점 :**
- 노이즈가 많으면 노이즈도 같이 증폭됨 = 불필요한 신호도 전달.
- 모든 신호를 그대로 다시 전달하고 트래픽을 구분하지 못함.

# 4. 게이트웨이

: 서로 다른 네트워크를 연결하려 통신을 가능하게 하는 장치.<br>
: 내부망과 외부망의 출입문 (공유기, 라우터 역할)

**네트워크 외부 vs 내부**
- 외부 네트워크 : HTTPS프로토콜 ↔ QUIC프로토콜
- 내부 네트워크 : 게이트웨이

**왜?**
- 서로다른 네트워크를 연결할 때 사용. (통로)
- 데이터 변환, 필터링을 위해서 : IP 주소 변환, 프로토콜 변환 역할도 같이 수행.

**LAN 목적지를 찾을 수 없을때** (목적지가 같은 네트워크 안에 없을때)
- 내가 목적지를 못본다면…? 외부 네트워크 구나? → 기본 게이트웨이에 전달.

> 💡 내 컴퓨터 → (외부 목적지) → 기본 게이트웨이 → 인터넷망 → 목적지 서버

### 게이트웨이의 종류

1. **기본 게이트웨이** : 외부 네트워크를 사용할때 거치는 출입문
2. **API 게이트웨이** : 클라이언트 → API게이트웨이 → 회원 API, 주문 API, 결제 API

# 5. 라우터 <span style="color:red">(왕 중요)</span>

서로 다른 네트워크를 연결하고 IP주소를 보고 패킷이 갈 다음 경로를 결정하는 장비.<br>
최종 목적지가 아니라 **다음 홉을 안내한다.**

> 💡 내 PC → 집 라우터 → 통신사 라우터 → 중간 라우터들 → 목적지 서버

**라우터 vs 스위치**<br>
스위치 : MAC주소를 보고 같은 네트워크로 보냄<br>
라우터 : IP를 보고 패킷을 다른 네트워크로 보냄.

**인터넷**<br>
≠ 하나의 네트워크<br>
= 엄청나게 쪼개져 있는 다양한 네트워크의 집합.<br>
네트워크와 네트워크 사이에서 패킷이 다음에 어디로 가야할지 결정.

### 라우터 동작 방식

1. 패킷을 받는다. (목적지 IP와 출발지 IP)
2. 받은 패킷에서 목적지 IP확인 : 어떤 네트워크로 보내야 할까?
3. 내부 요청, 외부 요청 구분
4. 외부 라우팅의 실제 경로를 라우팅 테이블을 확인함.
5. <span style="color:red">목적지 서버 방향으로 전달함(한번에 목적지로 가는 게 아님)</span>

# 6. 허브

: 네트워크에서 데이터를 여러개의 장치로 전달하는 장치. (연결장치)<br>
: 전달하는 데이터의 내부를 보지 않고 그냥 전달만 함. (데이터 분석 X, 필터링 X)

장점 : 저렴함, 구성이 단순함.<br>
문제점 : 불필요한 트래픽이 많음. 보안적이지 않음, 충돌이 발생함.

---

# 7. 스위치

**허브 vs 스위치**<br>
허브 : 연결되어 있는 모든 장치에 트래픽을 보내고 목적지를 판단하지 않음<br>
스위치 : 필요한 장치한테만 보낸다(L2)

**Flooding** : 스위치가 목적지 Mac주소를 모를때 → 일단 모든 포트로 보내고 목적지를 찾으면 맥 주소 테이블을 업데이트 함.

**사용이유)**
- 데이터를 정확하게 전달할 수 있음. 불필요한 트래픽 감소, 충돌 감소
- 보안성 향상 : 목적지가 아닌 다른 곳에 전달될 가능성이 낮음.

**스위치 vs 라우터**<br>
스위치 : LAN내부에서 사용, MAC 주소를 봄<br>
라우터 : 네트워크 간 사용, IP주소만 봄.

---

# 8. 브릿지

: 두개 이상의 LAN 세그먼트를 연결하고 MAC주소를 기준으로 필요한 트래픽만 전달하는 장비.

ex) 1층 LAN, 2층 LAN, 3층 LAN = 브릿지가 연결함.

- 모든 데이터를 연결하지 않는다. (L2에서 동작)
- MAC주소를 읽고 우리 LAN이면 안에서 동작하고 반대편 LAN이면 이동 시킴

**왜?**
- LAN을 연결할때 (LAN A - 브릿지 - LAN B)
- 불필요한 트래픽을 줄일 때
- 충돌범위도 적어짐.

**브릿지 vs 스위치**<br>
브릿지 : 소프트웨어기반 처리, 포트수가 적음.<br>
스위치 : 하드웨어 기반 처리 = 빠름, 포트수가 많음.

## 용어정리

**Network** : 연결된 장치끼리 데이터를 전달 받는것.<br>
**NIC** : 노드들이 네트워크에 연결될 수 있게 하는 하드웨어. 호스트랑 네트워크 사이에서 데이터를 보내고 받는 역할.<br>
**MAC Address** : NIC에 부여된 고유한 물리적 식별자. LAN 안에서 장치를 구분하는 주소.<br>
**ARP** : IP주소에 해당하는 MAC주소를 알아내는 프로토콜.<br>
**Gateway** : 서로 다른 네트워크를 연결하려 통신을 가능하게 하는 장치. 내부망과 외부망의 출입문.<br>
**Router** : 서로 다른 네트워크를 연결하고 IP주소를 보고 패킷이 갈 다음 경로를 결정하는 장비.<br>
**Switch** : 같은 네트워크 안에서 MAC주소를 보고 필요한 장치에만 데이터를 전달하는 장비.<br>
**LAN** : 제한된 공간에서 장치들이 빠르게 통신하고 자원을 공유하기 위한 내부 네트워크.<br>
**VLAN** : 하나의 물리적인 네트워크를 여러개의 독립된 네트워크처럼 나누는 기술.
