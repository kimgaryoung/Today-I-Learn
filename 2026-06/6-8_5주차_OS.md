# [한줄정리]

- **운영체제** : 사용자가 컴퓨터의 동작원리를 몰라도 OS가 소프트웨어와 하드웨어를 관리해 사용할 수 있게 해줌.
- **Kernel** : 하드웨어 자원에 직접 접근해 관리하는 OS 계층.
- **System Call** : 유저 모드에서 커널 모드로 전환하는 호출.
- **Virtual Memory** : 프로그램 기준의 주소로 mmu로 물리주소와 매핑되어 동작함. (↔ 물리주소: 하드웨어 기준 주소)
- **Swap** : 사용하지 않는 데이터를 스왑 공간(DISK내 별도의 공간)으로 이동하여 RAM메모리를 확보하고 필요할 때 다시 메모리로 복구하는 방식
- **Paging** : 프레임 기준이 아닌 논리 주소인 페이지를 고정 크기 만큼 분할하는 방식.
- **Segmentation** : 프로세스 단위를 기준으로 논리주소를 분할하는 가변 분할 방식
- **Internal / External Fragmentation** :<br>
  - 내부 단편화 : 할당된 메모리 블록보다 프로세스가 필요한 공간이 작아 낭비되는 공간이 많아지는 것.<br>
  - 외부 단편화 : 프로세스가 들어갔다 나가면 메모리 중앙에 빈공간이 생겨 연속된 프로세스를 담을 수 없는 것.
- **Process** : OS로 부터 독립적인 메모리를 할당받아 실행되는 프로그램.
- **Thread** : 프로세스 내에서 메모리를 공유하여 병렬작업을 수행하기 위한 최소 단위.
- **IPC** : OS가 프로세스 간 통신을 위해 제공하는 통로.
- **PCB** : 프로세스의 실행정보를 담고 있는 자료구조.

> 논리주소를 분할 하는 거랑 물리주소를 분할 하는게 왜 그렇게 쓰는걸까?<br>
> → 프로세스 입장에서는 메모리가 연속되어 빈 공간을 찾을 필요가 없어서 메모리 관리가 훨씬 쉬워지기 때문.(자원 사용 효율 때문)

# 1. 운영체제

역할 : 사용자 인터페이스(사용자가 명령을 내릴 수 있는 창구)를 제공함.

### 왜?

1. 자원 관리
2. 사용자 편의성
3. 작업 조율 (멀티 태스킹)
4. 보안 및 안정성 : 사용자가 하드웨어를 직접 조작하지 못해 데이터와 시스템을 보호함.

**시스템콜** : 유저모드에 프로그램이 운영체제의 커널 기능을 요청하는 통로 (인터페이스)<br>
ex ) 나 파일 읽고 싶은데.. 나 메모리 더 줘…

**커널**<br>
: 하드웨어 자원을 직접 관리하고 하드웨어와 프로그램 사이의 중재 수행.

### 1-1 리눅스

1. 오픈소스(무료), 생태계 구축 잘되어 있음
2. 서버운영에 적합함 - 안전성이 높고 가벼움.
3. 대용량 데이터 처리시 CLI가 제어가 상당히 강력함.<br>
   ex) 서버 300대를 GUI로 한다고 가정하면 클릭이나 usb를 사용하는데 CLI보다 불편함.

### 1-2 유저모드랑 커널모드

**왜?**<br>
프로그램은 작은 버그에도 오류가 발생하는데 해당 오류가 하드웨어에서 접근하면 문제가 생길 수 있어서 커널모드와 유저 모드를 나눠서 권한을 분리함.

**유저 모드** : 사용자 응용 프로그램이 실행되는 환경 (user interface , system call)<br>
**커널 모드** : 운영 체제의 핵심 기능들(파일 열기, 메모리 쓰기, 네트워크 전송, I/O)과 하드웨어가 동작하는 환경 (kernel)

Ex 유저모드, 커널모드 사용 예시 : 유저모드 → 시스템 콜 → 커널 모드 → 결과 반환 → 유저 모드

```java
FileReader reader = new FileReader("test.txt");
int c = reader.read();
```

유저모드 : read()메서드가 OS에게 파일 읽어 달라 요청. →<br>
JVM내부 C언어가 시스템 콜로 OS커널에 요청을 전달→<br>
커널모드 : 시스템 콜로 인터럽트 발생해 커널 모드로 전환됨. →<br>
커널이 실제 "test.txt" 파일을 읽어옴. → 결과를 유저에게 전달→<br>
다시 유저 모드로 복귀.

# 2. 메모리 구조

: 가상주소를 4가지 기준으로 나누어 관리하는 방식.<br>
RAM - Code, Data, Heap, Stack

- **code영역** : 우리가 작성한 명령어, 코드 (읽기 전용 - 실행중에 변경되면 안되니까)
- **data영역** : 전역 변수, 정적 변수
- **heap 영역** : 동적 공간 - 파일내용, 객체, 사용자가 입력한 긴 텍스트
- **stack영역** : 임시 데이터 - 지역변수, 매개변수, 함수 호출 내역

### 왜 나누지?

1. 안정성 확보 - 사용 중인 메모리를 다른 프로세스가 해제하거나 덮어쓰는 걸 방지하기 위해서 Code영역을 두고 읽기 전용으로 사용함.
2. 자원 관리 - 프로그램 종료까지 들고 있을 메모리(데이터 영역)와 쓰다 버릴 메모리(스택 영역)을 분리해서 자원을 효율적으로 씀.
3. 유연성을 제공 - OS는 사용자가 실행전까지 메모리가 얼마나 필요한지 모름. heap이라는 공간을 사용해서 크기를 유연하게 사용할수 있다.

### 2-1 메모리 관리자

CPU ↔ Memory ↔ Disk

- 메모리 = 작업대
- CPU = 실제 작업
- DISK = 실제 데이터 있는 곳.

**CPU와 DISK의 처리속도가 문제!!!!**<br>
: cpu에 비해서 disk가 너무 느림.

**왜?**

1. 제한된 자원을 최적으로 사용 - 메모리는 비싸고 한정적인 자원이라 메모리를 빈공간 없이 최대한 활용하기 위해서 사용.
2. 프로세스 간 충돌 방지 - 하나의 운영체제 위에 돌고 있는 여러개의 프로그램들이 같은 메모리 공간에 접근해서 충돌하는 걸 방지함.
3. 물리적인 메모리의 한계 극복 - 메모리가 부족해지면 Disk의 저장공간을 빌려서 사용함. (swap방식)

# 3. 메모리 주소 체계

메모리를 1byte의 공간으로 나누고 주소를 부여함.(논리 주소)

### <span style="color:red">3-1 메모리 주소가 동작하는 방식 - 물리주소, 논리주소 (중요!!!!!!!!!!!)</span>

OS는 하드웨어 ram에 애플리케이션이 접근 못하게 차단하는 동시에 동작하기 위해 어플리케이션이 메모리에 접근하고 할당도 해야함. → 메모리 주소 분리.

**논리 주소(가상 주소)** : 프로그램이 바라보는 메모리 주소, 가상의 주소 (실제 메모리 주소 X, 프로그램 기준)<br>
**물리 주소** : 실제 Ram에 납땜되어 있는 물리적인 전기 주소

**MMU** : 메모리 관리 장치, 주소 변환을 실행하는 장치

- CPU : 메모리 프로그램에서 10번 주소에 있는 걸 가져와 명령.

cpu → 가상주소 → mmu → page table → 물리주소 → ram

| 가상 | 물리 |
|---|---|
| 0 | 0x23 |
| 1 | 0x50 |
| 2 | 0x64 |

### 3-2 메모리 관리 기법 (메모리 오버레이, 메모리 스왑)

: 메모리가 부족할때 사용하는 기법

**3-2-1 메모리 오버레이**<br>
: 제한된 메모리 환경에서 프로그램 필요한 부분만(개발자가 코드의 일부를 모듈로 쪼갠 부분만) 메모리에 로드하여 실행하는 기법. 같은 공간에 필요한걸 덮어쓰는 형식.<br>
단점) 개발자가 직접 해야하는게 많아져 개발 난이도가 올라가는 기법이라 지금은 잘 안씀.

**3-2-2 메모리 스왑**<br>
: 사용하지 않는 데이터를 스왑 공간(DISK내 별도의 공간)으로 이동하여 RAM메모리를 확보하고 필요할 때 다시 메모리로 복구하는 방식.

단점)
- <span style="color:red">메모리가 많이 부족한 경우에는</span> 스왑 공간에서 메모리로 불러오고 쓰는데 시간이 오래걸려 스왑처리 자체에도 속도가 많이 걸리고 프로세스를 점유해서 멈춘것 처럼 보인다.
- 쿠버네티스와 도커에서는 스왑 사용이 안된다. (kill후 재시작)

tip) 스왑을 마구잡이로 쓰면 터질 수 있어서 잘 설정을 해야함. (찰리왈 특이한 케이스 아니면 스왑을 안쓰려고함)

📷 [이미지: 메모리 스왑 동작 방식 다이어그램 - 메모리 ↔ 스왑 인/아웃 ↔ 보조기억장치(스왑 영역)]

**메모리 오버레이 vs 스왑**

| | 오버레이 | 스왑 |
|---|---|---|
| 관리주체 | 프로그래머 | OS |
| 관리 단위 | 하나의 프로그램 내부의 모듈 단위 | 실행중인 프로세스 단위. |
| 목적 | 단일 프로그램의 크기 제한 극복 | 여러 프로그램을 동시에 실행하기 위한 공간 확보 |

# 4. 메모리 분할

<span style="color:red">**\*\*내부 단편화**</span> : 할당된 메모리 블록보다 프로세스가 필요한 공간이 작아서 버려지는 공간이 많은것. (메모리 낭비)

<span style="color:red">**\*\*외부 단편화**</span> : 프로세스 사용후 메모리 중간에 빈 공간이 생겨 메모리가 연속적이지 못해 이후 큰 프로세스를 넣지 못하는것 (공간 부족)

**왜?**<br>
다중 프로세스 환경의 한정된 메모리 자원을 충돌 없이 효율적으로 나눠 써야 상황에서 메모리 공간을 특정한 단위로 쪼개서 사용하는 방법.

### 4-1 고정 분할 방식

: <span style="color:red">물리 메모리</span>를 고정된 크기로 사전에 나누고 그 블록에 프로세스를 하나씩 넣어줌, 임베디드 환경에서 사용

장점 : 관리가 상당히 쉽다. 프로세스 할당 속도가 빠르고 프로세스 들끼리 충돌 가능성이 낮다.<br>
단점 : <span style="color:red">내부 단편화</span> (메모리 공간 낭비)

### 4-2 가변 분할 방식

: <span style="color:red">물리 메모리</span>를 프로세스의 실제 크기에 딱 맞춰 동적으로 할당하는 방식

장점 : 메모리 낭비 없이 효율적임.<br>
단점 : <span style="color:red">외부 단편화</span> (공간부족)

### 4-3 페이징

: <span style="color:red">논리 메모리</span>를 고정된 크기로 잘라서 저장한다.

장점 : 메모리를 연속적으로 비워둘 필요가 없다.<br>
단점 : 메모리 추가 사용, 주소 변환 시간 추가 사용.
- page table을 사용하기 위해서 메모리가 추가로 필요함.
- 논리주소를 물리주소로 변환할 때 추가적인 시간이 걸린다.

### 4-4 세그멘테이션

: <span style="color:red">논리 메모리</span>에 프로그램을 논리적인 의미 단위로 잘라서 연속적으로 보관.

장점 : 프로그램의 구조가 그대로 반영되며 데이터 보호와 공유가 편하다.<br>
단점 : 세그먼트 크기가 각각 달라 외부 단편화가 발생할수 있음.

### 4-0 가상 메모리

: 프로세스에게 가상 주소로 구성된 연속적인 메모리 공간을 제공하는 메모리 관리 기법.

왜?) 물리적인 RAM 보다 큰 프로그램을 실행하면서 동시에 여러개의 프로세스를 안전하게 실행하기 위해.

**현대 OS사용 방식** ) 페이징과 세그멘테이션 혼합사용.<br>
→ 세그멘테이션(의미단위로)으로 먼저 나눈후 그걸 페이징(크기단위)으로 나눈다.

> **[퀴즈]** Q 세그멘테이션 방식에서 메모리를 나누는 논리적 기준에 대한 설명으로 옳은 것은? **(A)**<br>
> A. 함수 단위로 나눈다.<br>
> B. 프로세스의 실행 순서로 나눈다.<br>
> C. 사용자가 직접 코드블럭을 지정한다<br>
> D. 운영체제가 물리적으로 나눈다.

# 5. 프로세스와 스레드 ⭐

**프로세스** : 실행중인 프로그램의 하나의 흐름. 운영체제한테 자원을 할당 받아서 독립적으로 실행되는 단위.<br>
**스레드** : 프로세스 내에서 병렬처리를 위해서 생성되는 실행 흐름의 최소단위.

📷 [이미지: Thread와 Process 비교 다이어그램]

**왜?**<br>
성능을 최적화하면서 가장 저렴하게 서비스를 개발하는게 우리의 목표이기 때문.<br>
⇒ 프로세스는 멀티태스킹을 어떻게 수행하는지 이해하기 위해서 필요하고 스레드는 동시성과 병렬성을 활용해서 속도와 반응성을 극대화 하는데 필요함.

| 구분 | 프로세스 | 스레드 |
|---|---|---|
| 메모리 | 독립된 공간 사용 (Code, Data, Heap, Stack) | 프로세스 내 메모리 공유 (Code, Data, Heap) |
| 통신 | 복잡함 (프로세스 간 통신 필요) | 용이함 |
| 안정성 | 서로 영향을 주지 않아 높음 | 하나가 죽으면 전체 프로세스에 영향 |
| 속도 | Context Switching 비용 큼 | Context Switching 비용이 작아 빠름 |

⚠️ 스레드가 많다고 무조건 좋아지는 건 아님.

# 6. IPC (Inter-Process Communication)

: 프로세스간 통신 (프로세스는 메모리가 독립적이라 상호 작용을 위해 OS가 제공하는 것.)

**[IPC 방식 2가지]**

1. **메시지로 전달**<br>
   : 프로세스 A → 커널 → 프로세스 B<br>
   장점) 직접적인 메모리 공유 없이 안전하게 통신할 수 있음.<br>
   단점) 통신 속도 느림.

2. **공유 메모리**<br>
   : 프로세스들이 서로 공유할 수 있는 메모리 공간을 만드는 방식<br>
   장점) 통신 속도가 빠름.<br>
   단점) 접근하는 프로세스가 많은 경우에 동기화 문제가 일어남.

# 7. PCB (Process Control Block)

: OS가 각 프로세스를 효율적으로 관리하기 위해서 모든 실행 정보를 담아두는 핵심 자료구조. (스케줄링 최적화에 필요함)

**왜?**<br>
CPU가 여러 개의 프로세스를 아주 빠른 속도로 번갈아 가며 실행함. (CPU = 연산장치)<br>
CPU는 컨텍스트 스위칭 이후에 어떤 작업 중인지 기억하지 않기 때문에 PCB에 작업 정보를 저장해뒀다가 불러옴.

---

## 용어정리

**동시성** : 작업을 작은 단위로 나눠서 짧은 실행시간을 할당하고 관리함. 하나의 CPU내에서 일어나는 스케줄링임.<br>
**병렬성** : 여러개의 CPU코어를 활용해서 물리적으로 여러 작업을 동시 수행하는 것<br>
**스케줄러** : 시스템의 자원을 분배하기 위해서 프로세스나 스레드의 실행순서를 관리하는 주체<br>
**스케줄링** : cpu(자원)를 사용할 프로세스와 스레드들이 사용할 순서를 정하는 OS 규칙과 정책<br>
**Multilevel Queue** : 프로세스 종류별로 큐를 나누고 큐 마다 다른 스케줄링 알고리즘을 적용하는 방식.
